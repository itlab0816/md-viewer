# 제품 비전

## 핵심 가치

> "기존 마크다운 뷰어보다 훨씬 아름답게 보여주는 것"

기존 마크다운 뷰어들은 기능은 충분하지만 **투박하다**. MD Viewer는 콘텐츠를 읽는 경험 자체를 아름답게 만드는 것을 최우선으로 한다.

---

## 설계 원칙

1. **콘텐츠가 주인공** — UI는 최대한 뒤로 빠지고, 글이 돋보여야 한다
2. **즉각적인 피드백** — 설정을 바꾸면 보면서 바로 반영된다
3. **감각적인 기본값** — 설정 안 건드려도 이미 충분히 예쁘다

---

## 개발 우선순위

### 1단계 — 테마 시스템 ✅ 완료

- [x] 테마 프리셋 5종 (Minimal Dark/Light, GitHub, Notion, Sepia)
- [x] 폰트 패밀리 선택 (System, Pretendard, Serif, Mono)
- [x] 코드 블록 테마 6종 (Shiki)
- [x] 본문 너비 / 줄간격 / 글자 크기 슬라이더
- [x] 우측 슬라이드 패널에서 실시간 변경
- [x] 마크다운 요소별 ProseStyle 커스터마이징

### 2단계 — 읽기 경험

테마 위에 읽기에 특화된 기능.

- [ ] 집중 모드 (Distraction-free — 사이드바/탭 숨김, 본문만)
- [ ] 읽기 진행바
- [ ] PDF / 인쇄 내보내기

### 3단계 — 탐색 / 생산성

콘텐츠가 많아졌을 때 편의성.

- [x] 파일 내 검색 (Ctrl+F)
- [ ] 폴더 전체 글로벌 검색
- [ ] 커맨드 팔레트 (Ctrl+P)

## UI 구조 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| 설정 UI | 우측 슬라이드 패널 | 뷰어 보면서 실시간으로 바꿔야 취향 판단 가능 |
| 색상 기반 | iOS 다크 모드 | 투박하지 않고 세련된 검정 계열 |
| 테마 단위 | 폰트 + 색상 + 줄간격 + 본문 너비 + 코드 스타일 묶음 | 하나 고르면 전체가 맞춰짐 |
| 플랫폼 | 데스크탑 우선, 웹/앱은 별개 프로젝트 | 각 플랫폼 특성에 맞게 따로 |
| 에디터 통합 | Split 뷰 (에디터 + 뷰어 나란히) | WYSIWYG는 마크다운 커스텀 요소(Mermaid, KaTeX 등) 때문에 구현 복잡도가 너무 높음 |
